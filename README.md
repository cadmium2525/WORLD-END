# WORLD END

> 世界で最初に200面の最終ボスを倒した1人が、全プレイヤーのゲームを終わらせる。

スマートフォン（横向き・両手の親指操作）優先の高難度2D横スクロールアクション。全200面。
1〜79面はオートセーブ、**80〜100面はノーセーブ**の連続チャレンジ（100面はボス）。
101面からは **20面ずつのノーセーブ区間** が5つ続き、200面に真の最終ボスが待ちます。
200面のボスを倒し、サーバーがクリアを承認した最初の1人で世界が終わります。

- ゲーム本体：TypeScript + Vite（Canvas 描画）→ GitHub Pages
- 状態API：Cloudflare Workers + D1（無料枠内）
- 画像・音：すべてコードで生成（外部素材なし）

## 遊ぶ・動かす

```bash
npm install
npm run dev        # http://localhost:5173 （スマホ実機は同じWi-Fiから http://<PCのIP>:5173）
```

サーバー未接続のときは「オフラインモード」で動きます（世界の終了判定なし）。
サーバーとつなぐ方法は **[docs/CLOUDFLARE.md](docs/CLOUDFLARE.md)** を見てください。

### 操作

| | 移動 | ジャンプ | その他 |
| --- | --- | --- | --- |
| スマホ | 左下の ◀ ▶ | 右下の JUMP | 右上 II で一時停止 |
| PC | ← → / A D | Space / Z / ↑ | R：やり直し、Esc / P：一時停止 |

ゲームパッドにも対応しています。ボタンの大きさ・濃さ・位置はタイトルの「設定」で調整できます。

### テストプレイ用機能

URL の末尾に `?debug=1` を付けると、タイトル画面に **面選択・無敵** が出ます（一時停止メニューに「この面をスキップ」も出ます）。

- 例：`http://localhost:5173/?debug=1`
- 面選択の範囲は 1〜200面。ノーセーブ区間の最初の面（80, 101, 121, 141, 161, 181）を選んだ場合は通常どおりサーバーに記録されます
  （101面以降は、その区間のチケットを持っている場合のみ）。区間の途中の面を選ぶと非公式になります
- 無敵・スキップを使ったチャレンジはサーバーに公式記録として送られません（スキップした区間の次の区間のチケットも発行されません）
- 本番公開時は GitHub の Actions 変数 `ALLOW_DEBUG` を `false` にすると完全に無効化されます

## ステージエディタ

`editor.html`（公開後は https://cadmium2525.github.io/WORLD-END/editor.html 、`?debug=1` のタイトルからもリンクあり）で、
面ごとに手作りステージを作れます。手作りした面は自動生成より優先されます。PC での操作を想定しています。

- 地形・トゲ・崩れる床・スイッチ・敵・移動床・砲台・スタート・ゴールを配置
  （101面以降のギミック：バネ・風・氷・コンベア・扉・重力反転・圧殺ブロック・レーザー・ノコギリ・オーブ・鍵、暗闇・迫る壁/溶岩の設定も可）
- 面は 1〜199面から選択（100面・200面のボス面は対象外）
- 敵や移動床の向き・速さ・移動距離・タイミングを調整
- その場でテストプレイ（無敵・選択した列から開始も可）
- 🤖 ボット検証：自動攻略ボットがクリアできるか確認し、動きを再生できる
- 自動生成の面を読み込んで手直しすることも、まっさらから作ることもできる
- 編集内容はブラウザに **下書き** として自動保存

### ゲームに反映する

1. エディタの「書き出し」→ ダウンロード（またはコピー）
2. GitHub で `src/shared/stage-data.json` を開き、鉛筆アイコンで全文を置き換えて Commit
3. 数分で GitHub Pages に反映
4. サーバー（Cloudflare）を使っている場合は、`worker` で `npm run deploy` も実行（サーバー側もステージを使って記録を検証するため）。
   更新し忘れると、ノーセーブ区間（80面以降）の開始時に「ステージがサーバーと一致しません」と表示されます

## ルール（200面版）

| 区間 | セーブ | 死亡・やり直し・中断/再読込の復帰位置 |
| --- | --- | --- |
| 1〜79面 | 1面クリアごとに次の面を自動セーブ | その面の最初 |
| 80〜100面（21面） | 80面に到達した時点でセーブ。途中はノーセーブ | 80面の最初 |
| 100面 | ボス面。撃破しても世界は終わらず、101面へ進む（「101面に到達 ― セーブされました」） | （80面へ） |
| 101〜120 / 121〜140 / 141〜160 / 161〜180 / 181〜200面（各20面） | 区間の最初の面（101, 121, 141, 161, 181）に到達した時点でセーブ。途中はノーセーブ | その区間の最初の面 |
| 200面 | 真の最終ボス。撃破をサーバーが承認した最初の1名が勝者となり、世界が終了 | （181面へ） |

- セーブ地点（チェックポイント）は 1〜80 の各面と 101, 121, 141, 161, 181面。判定は `src/shared/progress.ts`
  （`segmentStart` / `segmentEnd` / `isNoSave` / `CHECKPOINTS` / `FINAL_STAGE = 200`）にまとめてあり、ゲームとサーバーで共通です
- 画面上部の「ノーセーブ中 n/21」（80〜100面）「ノーセーブ中 n/20」（101面以降）で区間内の位置がわかります
- 100面版のセーブデータ（80面まで）は、そのまま続きから遊べます

### 101〜200面のワールドとギミック

101面以降は面ごとの **設計表**（`src/shared/stages2.ts` の `DESIGN`。面の型・主役のギミック・区間の並び）どおりに組み立てます。
1〜100面の生成は一切変えていません（`tools/stage-hash.ts` で確認）。

| ワールド | 面 | 名前 | 新しいギミック |
| --- | --- | --- | --- |
| 11 | 101〜120 | 天空の浮島 | バネ、風ゾーン（横・上昇気流）、雲の足場 |
| 12 | 121〜140 | 氷の宮殿 | 氷の床（すべる）、圧殺ブロック、つらら |
| 13 | 141〜160 | 鋼鉄の工場 | ベルトコンベア、点滅レーザー、軌道を回る回転ノコギリ |
| 14 | 161〜180 | 深淵 | 暗闇、空中ジャンプ回復オーブ、迫る壁・せり上がる溶岩 |
| 15 | 181〜199 | 終焉 | 鍵と扉、重力反転＋全ギミックの複合 |
| — | 200 | 世界の終わり | 真の最終ボス（3形態・体力9。攻撃の前に予兆あり。気絶中に踏む） |

- 面の型：通常 / 強制スクロール（迫る壁）/ 縦に登る（高さ17行より大きい面）/ 短い精密 / 敵ラッシュ / パズル（鍵と扉）/ 暗闇。
  101〜199面で同じ型が3面続くことはありません
- 新しいギミックは「導入（単独で易しく）→ 応用 → 複合」の順に登場します
- BGM はワールド11〜15で別の曲、100面ボスと200面ボスも別の曲です

### サーバーの検証とチケット

- サーバーとの「挑戦（セッション）」はノーセーブ区間1つ単位です。区間の最初の面を始めるたびに開始し、クリアした面ごとに入力ログを送って検証します
- 区間の最後の面（100, 120, 140, 160, 180面）まで検証に成功すると、サーバーが次の区間用の **チケット**（署名付きの文字列）を発行し、ブラウザに保存されます
- 101面以降の区間を始めるには、その区間のチケットが必要です。セーブデータを書き換えて181面から始めても、チケットがなければサーバーは受け付けません
- チケットが無い・無効な場合も遊ぶことはできますが、その区間は「公式記録の対象外」になります（画面上部とメッセージで表示）。
  世界を終わらせられるのは、80面から200面まで全区間をサーバーで検証できたプレイだけです
- 同じチケットは何度でも使えます（区間の途中で死ぬたびに区間の最初から始め直すため）。改ざんしたチケットや、別の区間のチケットは拒否されます

## 構成

```
src/shared/     ブラウザとサーバーで共通のコード
  sim.ts        決定論的ゲームシミュレーション（整数演算のみ・60fps固定）
  progress.ts   進行ルール（セーブ地点・ノーセーブ区間・最終面）
  stages.ts     200面のステージ（手作りがあればそれを、なければ面番号から自動生成。1〜100面の生成）
  stages2.ts    101〜200面の設計表と組み立て、200面ボスの面
  stage-data.json  ステージエディタで作った手作りステージ
  stageFormat.ts   手作りステージのデータ形式
  solver.ts     自動攻略ボット
  replay.ts     入力ログの圧縮と検証用の再生
  name.ts       プレイヤー名の検証
src/client/     ブラウザ側（描画・入力・音・UI・セーブ）
src/editor/     ステージエディタ
worker/         Cloudflare Workers の状態API と D1 のスキーマ
tools/          開発ツール（自動攻略ボット、ステージ表示、結合テスト、ブラウザでの進行テスト）
docs/           Cloudflare の手順書
```

### 不正対策のしくみ

ゲームの物理計算は整数だけで行う「決定論的シミュレーション」になっていて、同じ面・同じ入力なら
ブラウザでもサーバーでも必ず同じ結果になります。80面以降（ノーセーブ区間）では1面クリアするごとに
**入力ログ（数十〜数百バイト）** をサーバーに送り、サーバーが同じシミュレーションで再生して
本当にクリアしているかを確認します。

- 面の順番飛ばし・偽のログ・死亡を含むログ → 拒否
- 実時間と合わない記録（極端に早い／一時停止しすぎ）→ 拒否
- 101面以降の区間をチケット無し・改ざんしたチケット・別の区間のチケットで始める → 拒否
  （チケットは HMAC-SHA256 で署名。鍵はサーバーの secret `TICKET_SECRET`）
- 世界の終了は200面の検証成功時だけ。`UPDATE ... WHERE ended = 0` の条件付き更新 → 同時申請でも勝者は必ず1人

ただし企画書のとおり、ブラウザに配るプログラムである以上、完全なチート防止（自動操作ツール等）は保証できません。

## 開発ツール

```bash
npm run verify-stages          # 自動攻略ボットで全面がクリア可能か検証（数分）
npm run solve -- 37            # 37面だけ検証
npm run preview-stage -- 37    # 37面の地形をテキストで表示
npm run diversity              # 101〜199面の多様性（型・ギミック・長さ）を表示し、似た面の組を警告
npm run stage-hash             # 1〜100面が変更前（tools/baseline）とバイト単位で同一か確認
npm run determinism            # シミュレーションの決定論（clone・再生の一致）を確認
npm run e2e                    # ローカルサーバーとの結合テスト（全6区間・チケット・同時クリア。docs参照）
npx tsx tools/browser-progress.ts   # ブラウザ（Playwright）での進行ルールのテスト（docs参照）
```

## 本番公開の仕上げ（テストプレイ後に行う）

テストプレイ中はサーバーが **テストモード**（`MODE = "test"`）で動いており、200面をクリアしても
「検証成功」の記録が残るだけで世界は終わりません（100面のボスはどちらのモードでも世界を終わらせません）。テストが終わったら：

1. 難易度の調整を反映して push
2. 100面版のサーバーを使っていた場合は、DB を200面版に移行：`npm run db:migrate:remote`（worker ディレクトリで。docs参照）
3. チケットの署名鍵を登録（未登録の場合）：`npx wrangler secret put TICKET_SECRET`
4. `worker/wrangler.toml` の `MODE` を `"live"` に変更して `npm run deploy`（worker ディレクトリで）
   - テストモードで発行されたチケットは本番モードでは使えません（署名にモードが入っているため）。テスト中に101面以降まで進んだ人も、
     本番で公式記録を狙うには80面から挑戦し直す必要があります（遊ぶこと自体はできます）
5. 世界をリセット（テスト中のセッションを消す）：`/api/admin/reset`
6. GitHub の Actions 変数 `ALLOW_DEBUG` を `false` にして Pages を再デプロイ
7. 実機（iOS Safari / Android Chrome）で最終確認

手順の詳細は [docs/CLOUDFLARE.md](docs/CLOUDFLARE.md) の「本番モードへの切り替え」にあります。
